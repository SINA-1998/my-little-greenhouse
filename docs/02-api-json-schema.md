\## ۳. ساختار API و پایگاه داده (Supabase)



\* \*\*فضای ذخیره‌سازی (Supabase Storage CDN):\*\* دو باکت مجزا برای فایل‌های WebP گیاهان (۲۹ فایل) و گلدان‌ها (۲۵ فایل) جهت دریافت لینک مستقیم CDN.

\* \*\*۴ جدول اصلی پایگاه داده (PostgreSQL):\*\*

1\. `plants\_catalog`: کلید یکتا بر اساس `slug` (نام علمی `kebab-case`)، آدرس تصویر WebP در CDN، و ستون‌های ساختاریافته/JSONB برای کل اسکیمای شناسنامه و کلینیک گیاه‌پزشکی.

2\. `pot\_templates`: کلید یکتا بر اساس `pot\_id` (نام فایل `pot-\*.webp`)، نام فارسی، خانواده هندسی دهانه (`faceted`، `cylinder`، `urn`، `rect`)، آدرس تصویر WebP در CDN، و آبجکت `socketCalibration`.

3\. `pbr\_materials`: کلید رنگ (`white`، `black`، `mintPastel` و...)، نام فارسی، نوع لعاب پیش‌فرض (`finish`)، و آرایه‌های RGB برای `shadow`، `mid` و `highlight`.

4\. `user\_greenhouse`: جدول رابط برای گلخانه شخصی کاربر بدون تکرار دیتای گیاه؛ شامل `species\_id` (ارجاع به `plants\_catalog`)، `pot\_id` (ارجاع به `pot\_templates`)، `material\_id` (یا رنگ سفارشی Hex + نوع لعاب)، نام دلخواه گیاه، محل نگهداری (منزل، اداره، حیاط) و وضعیت آبیاری.





\* \*\*ورود خودکار اطلاعات (Seed Script):\*\* اسکریپت Node.js برای خواندن خودکار ۲۹ فایل JSON از پوشه لوکال و درج آن‌ها در `plants\_catalog`.

\* \*\*فراخوانی در فرانت‌اند:\*\* درخواست REST API به Supabase برای دریافت یکجای دیتای گیاه، تنظیمات دهانه گلدان و پالت PBR؛ کامپوننت `<PlantPotCanvas/>` بر اساس این پاسخ، گیاه را خودکار داخل دهانه گلدان قفل می‌کند.

\## ۴. قوانین سخت‌گیرانه محتوایی، کلینیکی و ممنوعیت‌های واژگانی



\* \*\*قواعد خروجی JSON:\*\*

\* خروجی خام و معتبر (`Raw JSON`)، انکودینگ اجباری `UTF-8` و پسوند `.json` (نه `.txt`).

\* تمام مقادیر توضیحی باید به \*\*فارسی علمی و آکادمیک\*\* نوشته شوند؛ نام‌های علمی گیاهان، پاتوژن‌ها (مانند `Pythium`، `Phytophthora`، `Erwinia chrysanthemi`)، ترکیبات قارچ‌کش/سم (مانند `Metalaxyl-M + Mancozeb`، `Fosetyl-Aluminum`) و واحدهای استاندارد (`g/L`، `pH`، `NPK`، `Lux`) با دقت بالینی حفظ می‌شوند.





\* \*\*قواعد اجباری فیلدهای نگهداری:\*\*

\* \*\*کلینیک گیاه‌پزشکی:\*\* دقیقاً \*\*۵ عارضه بالینی\*\* متمایز برای هر گونه با دسته‌بندی مشخص، علائم، علل ریشه‌ای، درمان گام‌به‌گام با دوز دقیق و پروتکل پیشگیری.

\* \*\*نور و تقارن:\*\* ذکر بازه لوکس دقیق و پروتکل چرخش گلدان با دو فیلد عددی `angleDegrees` و `intervalDays`.

\* \*\*اقلیم و تجهیزات تهویه (HVAC):\*\* الزام به تفکیک محیط منزل/اداره و ذکر دقیق فاصله ایمن از شوفاژ/بخاری و کوران کولر آبی/گازی.





\* \*\*ممنوعیت‌های واژگانی (Strict Lexical Bans) در پایپ‌لاین رندر تصاویر:\*\*

\* \*\*در پرامپت گیاهان (Zero-Vessel):\*\* ممنوعیت مطلق استفاده از واژگان مربوط به ظرف و گلدان (`pot`، `planter`، `vase`، `container`، `vessel`)؛ گیاه باید صرفاً با دیسک خاک رندر شود.

\* \*\*در پرامپت گلدان‌ها (PBR Base):\*\* ممنوعیت مطلق وجود گیاه، برگ، ساقه یا خاک (`Strictly NO plant, NO leaves`)؛ سطح گلدان باید سفید مات خنثی (`#F0F2F5`) با فضای داخلی تیره (`#222222`) باشد.





\* \*\*قانون یکپارچه‌سازی:\*\* ممنوعیت هرگونه تفکیک (مانند پیشوند `personal` یا `cat`) بین دارایی‌های شخصی و عمومی در نام‌گذاری فایل‌ها و جداول دیتابیس.

\## ۵. نقاط دقیق ناتمام در طراحی API گلدان‌ها و تصاویر



1\. \*\*اسکریپت SQL ساخت جداول و سیاست‌های دسترسی (Supabase DDL):\*\* کدهای `CREATE TABLE`، تعریف نوع دقیق ستون‌ها (تفکیک ستون‌های رابطه‌ای از `JSONB`)، کلیدهای خارجی (`Foreign Keys`)، ایندکس‌ها و قوانین RLS هنوز نوشته نشده‌اند.

2\. \*\*استخراج فایل کالیبراسیون اختصاصی ۲۵ گلدان:\*\* در حال حاضر فقط ۴ پیش‌تنظیم عمومی (`faceted`، `cylinder`، `urn`، `rect`) در `test.html` وجود دارد؛ مقادیر دقیق `socketCalibration` برای تک‌تک ۲۵ فایل `pot-\*.webp` هنوز استخراج و در یک فایل مرجع (مثل `pots-calibration.json`) تجمیع نشده است.

3\. \*\*فرمول نهایی تفکیک مختصات گیاه و گلدان (Dual-Socket Normalization):\*\* منطق تطبیق خودکار هر گیاه با هر گلدان در سطح مفهومی تعریف شده، اما قرارداد دقیق API برای تفکیک «پارامترهای ثابتِ دیسک خاکِ هر گیاه» از «پارامترهای ثابتِ دهانه هر گلدان» (تا با تعویض گلدان، `offsetY` و `scale` به صورت ریاضی و بدون دخالت کاربر بازمحاسبه شوند) هنوز کدنویسی نشده است.

4\. \*\*اسکیمای دقیق گلدان‌های مستطیلی چندگیاهی (`Multi-Slot Trough`):\*\* ویژگی `slots: \[1, 2, 3, 4]` برای دو گلدان مستطیلی (`pot-trough-fluted-rect.webp` و `pot-trough-minimal-box.webp`) صرفاً در حد ایده مطرح شده است؛ ساختار دقیق JSON برای مختصات هر جایگاه (`slotIndex`، `offsetX`، `maxScale`) و نحوه ذخیره یک گلدانِ حاوی چند گیاه در جدول `user\_greenhouse` هنوز طراحی نشده است.

5\. \*\*اسکریپت آپلود و تزریق خودکار (Seed \& Storage Upload Script):\*\* اسکریپت Node.js برای آپلود دسته‌جمعی ۲۹ تصویر گیاه و ۲۵ تصویر گلدان به Supabase Storage و ثبت خودکار ۲۹ فایل JSON در دیتابیس هنوز نوشته نشده است.

6\. \*\*تبدیل موتور گرافیکی به کامپوننت ماژولار React (`<PlantPotCanvas/>`):\*\* کل منطق PBR و کمان بیضی خاک فعلاً درون یک فایل تستی Vanilla JS (`test.html`) با شناسه‌های ثابت SVG (`#pbrPotFilter` و `#soilBottomClip`) قرار دارد؛ برای نمایش هم‌زمان چندین گیاه و گلدان در صفحه ویترین React، این شناسه‌ها باید داینامیک (`useId()`) شوند تا فیلتر رنگ و برش خاک گلدان‌ها با یکدیگر تداخل پیدا نکنند.
